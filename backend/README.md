# /backend — оффчейн-сервисы SixSec

**Статус: Фаза 3 начата.** Работает очередь модерации и аудит-лог. Данные — фикстуры.

## Что уже есть

| Модуль | Файл | Что делает |
|---|---|---|
| Домен | `src/domain.ts` | Типы, зеркалящие `programs/sixsec/src/state.rs`. Расхождение = баг |
| Источник данных | `src/chain/source.ts`, `mock.ts` | Интерфейс `ChainSource` + фикстурная реализация |
| Авторизация | `src/moderation/authorization.ts` | Право модератора + валидация решения |
| SIWS | `src/auth/siws.ts`, `base58.ts` | Вход по ed25519-подписи, nonce, сессии |
| Аудит-лог | `src/moderation/audit.ts` | Append-only JSONL: кто, когда, какой тир, причина |
| API + UI | `src/api/server.ts`, `dashboard.html` | Очередь модерации, `node:http`, без сборки |

## Запуск

```bash
cd backend
npm install
npm test          # 79 юнит-тестов, node:test, без фреймворка
npm run typecheck # tsc --strict --noEmit
npm run dev       # http://localhost:8787
```

Тесты идут через `node --experimental-strip-types`: шага компиляции нет. Отсюда
одно ограничение — **в коде нельзя использовать parameter properties**
(`constructor(private readonly x: T)`): strip-only режим стирает типы, но не
генерирует присваивание, и падает с `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`.

## Модель безопасности

**Backend не подписывает и не отправляет транзакции.** `POST /api/decisions`
проверяет право и корректность, пишет аудит-лог и возвращает описание инструкции
`moderate`, которую подписывает кошелёк модератора. Ответ всегда содержит
`"signed": false`. Скомпрометированный backend поэтому не может одобрить выплату.

`moderatorAuthority` читается из `PoolState` **через `ChainSource`**, а не из
конфига или env. Иначе безопасность программы сводилась бы к безопасности конфига
backend'а.

Порядок проверок намеренный: **сначала право, потом корректность решения**.
Иначе неавторизованный вызывающий изучал бы содержимое очереди по кодам ошибок
(`AlreadyDecided` и `InvalidTierId` раскрывают данные). По той же причине в SIWS
роль проверяется **после** криптографии: иначе перебором адресов можно выяснить,
какой из них является модератором.

### Вход: SIWS

| Шаг | Эндпоинт | Что происходит |
|---|---|---|
| 1 | `POST /api/auth/nonce` `{pubkey}` | Сервер создаёт одноразовый nonce, привязывает его к адресу и возвращает **готовый текст** |
| 2 | — | Кошелёк подписывает текст ed25519 |
| 3 | `POST /api/auth/verify` `{pubkey, signature, nonce}` | Сервер восстанавливает адрес из подписи, сверяет с `moderatorAuthority`, выдаёт сессию |
| 4 | `POST /api/decisions` + `Authorization: Bearer` | Решение от имени подтверждённого адреса |
| 5 | `POST /api/auth/logout` | Отзыв сессии |

Текст сообщения клиент **не собирает сам** — сервер отдаёт его целиком. Поэтому
расхождение формата между клиентом и сервером невозможно, а подмена полей
бессмысленна: подпись проверяется по тексту, восстановленному из записи сервера.

Свойства, покрытые тестами: nonce одноразовый и привязан к адресу; истёкший и
неизвестный nonce отклоняются; неудачная проверка nonce не сжигает; подпись от
другого домена, другого nonce или другого ключа не проходит; адрес и подпись
неверной длины отклоняются до криптографии; истёкшие nonce вычищаются при выдаче
(запрос nonce не требует авторизации, поэтому без очистки это готовый DoS);
сравнение токенов через `timingSafeEqual`.

Коды ответа: `401` не аутентифицирован или подпись не прошла · `403` не тот
кошелёк · `404` нет сабмишена · `422` решение некорректно · `202` принято, но не
подписано.

### Демо-ключ

Настоящего кошелька в браузере пока нет, поэтому для входа в дашборд сервер
создаёт ed25519-ключ **при каждом запуске** и отдаёт его на `/api/dev/demo-key`,
выставляя этот же адрес как `moderatorAuthority` фикстурного пула. Ключ нигде не
хранится и не является секретом: в этом режиме `ChainSource` — фикстуры и выплат
не существует. **Вне mock-режима эндпоинт возвращает 404** — это покрыто тестом,
а не только условием в коде.

## ⚠️ Чего здесь нет и что нельзя считать готовым

1. **В дашборде нет настоящего кошелька.** Вход подписывается демо-ключом через
   WebCrypto, а не Wallet Adapter'ом. Сам протокол SIWS при этом настоящий и
   проверен: сервер восстанавливает адрес из подписи. Заменить демо-ключ на
   Phantom/Solflare — задача клиента, а не backend'а.
   Dev-режим с заголовком `x-moderator` остался, но включается только через
   `SIXSEC_AUTH=dev` и по умолчанию выключен.
2. **Данные — фикстуры.** Программа не задеплоена даже на devnet. Дашборд
   показывает выдуманные сабмишены; баннер об этом не скрывается.
3. **Отправки транзакции нет вовсе.** Нет ни кошелька, ни RPC-клиента. Это
   следующий шаг после деплоя на devnet.
4. **Нет Postgres, BullMQ, Redis** из стека мастер-промпта §4. Аудит-лог пока
   JSONL на диске — этого достаточно для одного модератора и недостаточно для
   нескольких (нет конкурентного доступа и поиска).
5. **Нет авто-префильтра** (Q10), загрузки медиа (Q9), нотификаций, атрибуции.

## Стек

Node 22 · TypeScript 5.7 (strict) · `node:http` · `node:test`. Намеренно без
фреймворка и без ORM: зависимостей три, и `npm install` занимает секунды.
Postgres/BullMQ добавляются, когда появится реальная нагрузка, а не заранее.
