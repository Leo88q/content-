# WEB3 PROPOSITION — Proof-of-Retention: маркетинговая сеть, где платят за удержание

- **Дата:** 2026-09-21
- **Статус:** концепт-предложение. Не ADR, не решение. Отдельный продукт в отрыве от SixSec (по запросу заказчика «отойти от моей концепции»).
- **Связь с репозиторием:** независимый стратегический документ. Код SixSec здесь не используется как основание, но переиспользуемые части перечислены в §7.

## 1. Диагноз рынка (сентябрь 2026, с источниками)

Все основные каналы web3-маркетинга документированно сломаны, и рынок это
знает:

| Симптом | Факт | Источник |
|---|---|---|
| Квест-платформы производят наёмников | Galxe: >100K дневных активных кошельков в пиках, падение <20K через дни после конца наград. «Очередь заданий пустеет в момент получения награды» | hackernoon.com/why-most-web3-communities-are-built-to-collapse |
| Quest farming — системная проблема | «Хорошо документированная проблема quest-платформ: участники выполняют минимум для клейма без вовлечения в протокол» | apcollective.io/blog/web3-marketing-stack |
| InfoFi (post-to-earn) умер | «Крах InfoFi 2026 dismantled спам-Driven post-to-earn; рынок сдвинулся к верифицируемым ончейн-действиям и sybil-сопротивлению» | paragraph.com/@inspiralabs (Galxe post-InfoFi) |
| Ванильные метрики мертвы | DappRadar закрылся в ноябре 2025; «Dead Discord Syndrome»: метрика членов только растёт и никогда не падает, продолжая врать | hackernoon.com (там же) |
| Проблема — «users who matter» | «10 000 телеграм-участников за выходные, мега-KOL с 500K показов, 5 000 кошельков за 48 часов — и ничего из этого не даёт пользователей, которые депонируют, транзактируют, держат и возвращаются. Через полгода команда там же, минус $80K» | guerrillabuzz.com/blog/web3-user-acquisition |
| Стек фрагментирован | «Adequate coverage with poor integration: Discord-аналитика не связана с ончейн-данными, KOL-трекинг — с комьюнити-аналитикой. Решения — на анекдотах и интуиции» | apcollective.io (там же) |
| KOL-рынок живёт скриншотами | «Скриншоты постов — не отчётность. Публикация ≠ охват». Веттинг KOL рекомендуется по prior promo performance — вручную | shilikajain.com (KOL playbook); guerrillabuzz.com |
| Paid media задушен | Google/Meta/X ограничивают крипто-рекламу; стек структурно смещён в earned media и дистрибуцию через креаторов | apcollective.io (там же) |

**Ключевой вывод.** Вся индустрия борется с фермерами **детекцией**:
sybil-фильтры, паспортные скоры, credential-системы (Galxe Passport/Score).
Но фермеров породила **экономика**: мгновенная выплата за разовое действие.
Пока вознаграждение = f(действие), детекция — бесконечная гонка вооружений.
Никто не перевернул саму формулу выплаты. Это и есть белое пятно.

## 2. Флагманский концепт: Proof-of-Retention network

Рабочие названия: **Stayk** (stay + stake), Vestia, HoldPay.
Окончательное имя — отдельный ADR по процедуре ADR-0001/0008.

### 2.1 УТП (уникальное торговое предложение)

> **Единственный маркетинговый канал в web3, где вознаграждение вестится
> по retention-кривой приведённого пользователя. Фермер не может заработать
> экономически — детекция не нужна.**

Для проекта: «Вы платите не за клики, подписки и квесты. Вы платите только
за кошельки, которые остались. Метрика — CPRW, cost per retained wallet».

Для креатора: «Ваш трек-рекорд — не скриншоты, а верифицируемая статистика:
сколько приведённых вами кошельков дожило до D30. Его нельзя купить,
нельзя подделать, и он продаёт вас дороже любых подписчиков».

### 2.2 Механика (четыре блока)

**Блок 1. Эскроу вместо обещаний.**
Проект депонирует бюджет кампании в смарт-контракт до старта. Chargeback
невозможен: креаторы видят обеспеченность. Нераспределённый остаток
возвращается проекту по окончании кампании. (Модель пула с резервами
концептуально повторяет ADR-0006/0009 SixSec — резерв по худшему случаю,
выплата только из пула.)

**Блок 2. Вестинг вознаграждения по кривой удержания.**
Приведённый кошелёк достигает контрольных точек — креатору выплачивается
доля:

| Точка | Выплата креатору | Смысл |
|---|---|---|
| Wallet connect + целевое действие (swap/игра/депозит) | 0–20% (настраивается) | фильтр «пустого» трафика |
| Активен на D3 | +до 50% | отсекает однодневных фермеров |
| Активен на D7 | +до 80% | основной порог качества |
| Активен на D30 | 100% | полная ставка |

Кривая задаётся проектом в кампании. Награда креатора программно привязана
к **чужому поведению во времени**. Ферма из 500 кошельков обязана держать
активность 30 дней — это дороже вознаграждения. Сибил-атака перестаёт
окупаться не потому, что её поймали, а потому, что за неё не платят.

**Блок 3. Retention-quality score и атрибуционный граф.**
- Ончейн-сигналы: возраст кошелька, разнообразие протоколов, частота и реценция транзакций, отсутствие связей с известными фермерскими кластерами.
- Оффчейн-сигналы: события продукта через API проекта (сессии, уровни, депозиты), подписанные ключом проекта и дублируемые в граф — защита от «проект забыл отправить события».
- Северная метрика платформы: **CPRW — cost per retained wallet** (кошелёк, активный на D30, с целевым действием). Публичный бенчмарк по категориям (игры / DeFi / NFT) — сам по себе маркетинговый актив: «отчётность вместо скриншотов» как продукт.

**Блок 4. Публичный трек-рекорд креаторов.**
Каждый KOL/реферер/комьюнити накапливает верифицируемую историю:
приведено кошельков, доля доживших до D7/D30, по категориям проектов,
динамика по месяцам. Проекты выбирают креаторов по доказанному retention.
Это ручной vetting-фреймворк из guerrillabuzz.com («prior promo
performance»), превращённый в автоматический рынок репутации.

### 2.3 Почему это не «ещё одна quest-платформа»

| | Galxe / Zealy / Layer3 | Stayk |
|---|---|---|
| За что платят | за действие (follow, swap, quest) | за состояние во времени (остался активен) |
| Борьба с сибил | детекция (паспорта, скоры, фильтры) | экономика (вестинг делает ферму убыточной) |
| Метрика кампании | участников, клеймов, DAW | CPRW — retained wallets |
| Репутация креатора | отсутствует / субъективна | верифицируемый retention-трек-рекорд |
| Момент выплаты | мгновенно (→ дамп и уход) | по кривой (→ креатор заинтересован в качестве трафика) |
| Что накапливается | каталог квестов | атрибуционный граф «канал → удержание» |

### 2.4 Бизнес-модель

1. **Комиссия с исходов:** 10–15% от выплаченных вознаграждений. Платит проект; для креатора комиссия прозрачна.
2. **SaaS-подписка на граф:** дашборд атрибуции, когортный анализ, бенчмарки CPRW по категории — для маркетинг-команд. Бесплатный tier: только собственная кампания; платный: бенчмарки и конкурентные когорты.
3. **Boost-рынок (фаза 2):** креатор может продать часть будущего вестинга за немедленную выплату с дисконтом (покупатели — спекулянты на качестве трафика; дискон = функция его трек-рекорда). Решает главную боль — «деньги через 30 дней».

### 2.5 Ров (устойчивость к копированию)

- **Данные:** атрибуционный граф «какие когорты кошельков удерживаются с каких каналов и креаторов» — никто не может купить это за месяц; Galxe не может это построить, потому что её выплаты устроены иначе (и каннибализируют её revenue).
- **Треки креаторов:** репутация не переносится — топ-креаторы остаются там, где их история.
- **Двусторонний сетевой эффект:** проекты идут за проверенными креаторами, креаторы — за эскроу-бюджетами.
- **Инноваторский дилемма конкурентов:** quest-платформы зарабатывают на объёме кампаний и клеймов; модель «платить меньше за худших наёмников» для них — самоубийство revenue. Окно открыто.

### 2.6 Холодный старт

1. **Категория-клин: игры** (retention мерить проще всего: сессии, уровни; три игры заказчика — design partner №1).
2. Первые 10 кампаний — с нулевой комиссией и ручной верификацией событий («Волшебник страны Оз»): бот, таблицы, выплаты вручную. Цель — первые честные CPRW-бенчмарки.
3. Публичный отчёт «State of Retention in Web3 Gaming» по итогам первых кампаний — earned media (единственный канал, который работает при рекламных ограничениях).
4. Расширение: DeFi (funded wallet = депозит ≥ X дней), NFT, инфраструктура.

### 2.7 Риски и митигация

| Риск | Митигация |
|---|---|
| Креаторы не ждут 30 дней | Boost-рынок (дисконтная продажа вестинга); короткие кривые для первых кампаний (D7 = 100%) |
| Проект мухлюет с событиями продукта | События подписываются ключом проекта и дублируются в граф; спор — публичный арбитраж с репутационным уроном проекта; ончейн-сигналы не контролируются проектом |
| Last-touch войны за атрибуцию | Окна атрибуции в правилах кампании (например, 7 дней); мульти-тач деление награды — фаза 2 |
| Проекты не готовы платить за retention (дешевле наёмники в отчёте) | Целевая аудитория — команды после TGE-провала и фонды с portfolio-требованием качества; бенчмарки делают «дешёвых наёмников» видимыми |
| Юридика вестинг-выплат креаторам | Заключение до первого доллара (наследует дисциплину раздела 9 PRD SixSec); выплаты в стейблкоинах/нативных токенах проекта, не в собственном токене платформы, до аудита |
| Privacy: граф кошельков | Работаем с псевдонимными кошельками и агрегатами; никакого PII; opt-in для креаторов на публичность трек-рекорда |

## 3. Альтернативные концепты (слабее флагмана, но валидны как модули)

### B. Unified Attribution CRM («связать стек»)
Прямой ответ на фрагментацию: Discord + X + ончейн + UTM + продукт в одном
per-user journey графе. Реальная боль (apcollective: «adequate coverage
with poor integration»), но это B2B-SaaS без виральности и без уникального
УТП — конкурирует с Dune/Nansen-подобными. **Вердикт:** хороший модуль
внутри Stayk (блок 3), слабый как самостоятельный продукт.

### C. Proof-of-Play ad network
Играбельные промо (mini-app) с верифицированным вниманием: пользователь
проходит 6-секундную игровую сцену → подтверждённое внимание → награда.
Сильно как **формат креатива** для Stayk (что именно креаторы
дистрибутируют), но как самостоятельная сеть упирается в тот же вопрос
«кто платит и за что меряем». **Вердикт:** формат, не платформа.

### D. Public anti-vanity audit
Публичный аудит кампаний: «сколько из ваших 100K участников дожили до D30»
как сервис-отчёт. Вирусный маркетинговый потенциал (все боятся публичного
разоблачения), но одноразовый продукт. **Вердикт:** инструмент
привлечения внимания для Stayk, не бизнес.

Комбинация: **Stayk (A) — платформа; C — её креативный формат; B — её
аналитический модуль; D — её growth-маркетинг.**

## 4. MVP и план валидации (4 недели, до любого heavy-кода)

| Неделя | Что делаем | Критерий go/no-go |
|---|---|---|
| 1 | Лендинг с УТП + waitlist для проектов и креаторов; 20 кастдев-интервью (10 маркетинг-лидов web3-проектов, 10 mid-tier KOL) | ≥5 проектов и ≥20 креаторов в waitlist; боль «платим наёмникам» подтверждена словами «мы уже теряли на этом бюджет» |
| 2 | «Волшебник страны Оз»: одна кампания для одной игры вручную — Telegram-бот, реферальные ссылки, события из БД игры, выплаты вручную в USDC | кампания запускается без единой строчки смарт-контракта |
| 3 | Замер: приведено кошельков, D3/D7/D30 активность, CPRW против контроля (любая прошлая квест-кампания проекта) | CPRW известен и хуже/лучше контроля — цифра есть в любом случае; go = проекты говорят «готовы платить за этот CPRW» |
| 4 | Второй пилот с вестинг-кривой; решение о разработке контрактов и графа | ≥1 проект подписал письмо о намерениях на платную кампанию |

Ончейн-разработка (эскроу, вестинг, граф) — только после недели 4.
Юридическое заключение — до первых реальных выплат (параллельно с неделей 2–3).

## 5. Метрики продукта

- **Северная звезда платформы:** суммарный объём выплат, дошедших до D30-полной ставки (USD) — деньги, выплаченные за доказанно оставшихся пользователей.
- Кампании: CPRW по категориям, доля вознаграждений, доживших до каждой точки кривой (health кампании).
- Креаторы: retention-rate их когорт против медианы категории.
- Бизнес: take rate, gross retention проектов (возвращаются ли со второй кампанией).

## 7. Переиспользуемое из SixSec (если W6 = переиспользование)

| Актив SixSec | Куда ложится в Stayk |
|---|---|
| Пул призов без mint authority, резервы по худшему случаю (ADR-0006/0009) | эскроу кампании (блок 1) |
| `WorkerProfile.trust_score` + асимметрия штрафов | базовый слой sybil-скора креаторов (блок 3) |
| Backend: SIWS-аутентификация, очередь модерации, аудит-лог | админка кампаний и верификация событий |
| ADR-0011 (ончейн только граница безопасности, баланс off-chain) | тот же принцип: ончейн — эскроу и вестинг-выплаты, граф и скоры — off-chain |
| ADR-0012 (симуляционный слой не имеет пути к деньгам) | принцип для boost-рынка: спекулятивный слой не может создавать «retention» искусственно |
