# ADR-0005: Тулчейн — Anchor 1.2.0 + Solana CLI 4.1.2, `solana-*` пины линии ^3

- **Статус:** принято (отступление от текста промпта, зафиксировано явно)
- **Дата:** 2026-09-14
- **Решает:** дополнительный вопрос по версиям стека

## Контекст

Мастер-промпт предписывал «Anchor 0.32.x» и «Agave ветка 2.1.x». Заказчик ответил: «https://docs.rs интегрируй с этого сайта что нужно тут все актуальное».

**Ограничение среды, которое надо знать:** `docs.rs`, `crates.io`, `static.crates.io` и `index.crates.io` из этой песочницы **недоступны** — проверено, все четыре отвечают HTTP 000. Доступны `registry.npmjs.org` и `api.github.com`. Поэтому версии сняты не с docs.rs, а из исходников тега `v1.2.0` в `coral-xyz/anchor` через GitHub API. Для цели «зафиксировать корректные пины» это строже, чем docs.rs: это ровно те значения, которые попадут в `Cargo.toml`.

## Решение

| Компонент | Версия | Источник проверки |
|---|---|---|
| Anchor | **1.2.0** (релиз 04.09.2026) | `gh api repos/coral-xyz/anchor/releases` |
| Solana CLI / Agave | **4.1.2** | release notes Anchor 1.2.0: «The recommended Solana version is `4.1.2`» |
| `anchor-lang` (Rust) | 1.2.0 | `Cargo.toml` тега v1.2.0, `version = "1.2.0"` |
| `solana-account-info` | **3.1.0** | workspace `Cargo.toml` v1.2.0 |
| `solana-clock` | **3.0.1** | там же |
| `solana-cpi` | **3.0.0** | там же |
| `solana-pubkey` | **3.0.0** | там же |
| `solana-program-error` | **3.0.0** | там же |
| `solana-system-interface` | **2.0.0** | там же |
| `anchor-lang-idl` / `-idl-spec` | 0.1.4 / 0.1.0 | там же |
| Anchor TS-пакет | **`@anchor-lang/core` 1.2.0** (`@coral-xyz/anchor` застыл на 0.32.1) | `npm view` |
| `@solana/kit` | **8.3.0** (промпт говорил v5.x) | `npm view @solana/kit dist-tags` |
| `codama` | 1.10.2 | `npm view` |
| Тесты | LiteSVM 0.14.0 / Mollusk 0.14.0 / Surfpool 1.5.0 | Solana Changelog 16.07.2026 |

Ключевой вывод по крейтам: **Anchor 1.2.0 сам пинит `solana-*` линии `^3`**, при том что рекомендованный CLI — 4.1.2. Это не противоречие: релизы валидатора Agave 4.x версионируются независимо от SDK-крейтов. Значит **не надо** вручную поднимать `solana-*` до `^4` — это сломает сборку.

Дополнительно: MSRV в `[workspace.package]` тега v1.2.0 **не объявлен** (проверено). Матрица совместимости официального скилла указывает MSRV 1.89 для Anchor 1.1.x — беру 1.89+ как нижнюю границу, точный тулчейн зафиксирую фактической компиляцией в Фазе 2.

## Последствия

- `anchor test` в v1 по умолчанию гоняет **Surfpool** — это ровно то, что промпт требует в разделе 4, без ручной настройки.
- IDL в v1 хранится в Program Metadata; есть `verifiedBuild` (OtterSec `verify.osec.io`) — пригодится перед Фазой 8.
- Отступление от текста промпта осознанное. Если заказчик захочет 0.32.x — ветка жива (v0.32.2 вышел 14.09.2026), но это уходящая линия, и официальный скилл содержит отдельный гайд `anchor/migrating-v0.32-to-v1.md`.
- **Блокер сборки в этой среде:** `cargo`, `rustc`, `anchor`, `solana`, `docker` отсутствуют (проверено). Anchor-программу здесь не собрать и не протестировать, пока тулчейн не установлен. Не выдавать непроверенный on-chain код за готовый.
