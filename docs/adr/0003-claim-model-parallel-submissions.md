# ADR-0003: Модель claim'а — M параллельных сабмишенов на задание

- **Статус:** принято
- **Дата:** 2026-09-14
- **Решает:** Q5

## Контекст

Раздел 6 промпта оставлял выбор открытым («реши по данным пилота»), но предложенная схема уже принимала решение за нас: `claimed_by: Option<Pubkey>` + статус `Claimed` на `TaskAccount` = жёсткий эксклюзив на одного воркера. Менять это после деплоя — миграция аккаунтов.

Заказчик выбрал вариант «M параллельных сабмишенов».

## Решение

1. `TaskAccount.claimed_by: Option<Pubkey>` **убирается**. Вместо него:
   ```rust
   max_claims: u32,   // сколько параллельных воркеров допускает задание
   claim_count: u32,  // сколько уже взяли
   ```
2. Статус `Claimed` из перечисления `TaskStatus` **убирается**: при M параллельных воркерах задание остаётся `Open`, пока не набран `max_claims`.
3. Вводится отдельный аккаунт:
   ```rust
   #[account]
   pub struct ClaimAccount {
       pub task: Pubkey,
       pub worker: Pubkey,
       pub claimed_at: i64,
       pub expires_at: i64,   // лок N часов, N — on-chain параметр
       pub status: ClaimStatus, // Active | Expired | Submitted
   }
   ```
   PDA-seeds: `["claim", task.key(), worker.key()]` — это же гарантирует, что один воркер не возьмёт одно задание дважды.
4. `SubmissionAccount` ссылается на `ClaimAccount`, а не напрямую на task.
5. Анти-гонка: инкремент `claim_count` и создание `ClaimAccount` — в одной инструкции, с проверкой `claim_count < max_claims` под `#[account(mut, has_one = ...)]`. Иначе два воркера возьмут последнее место.

## Последствия

- Продукт работает как конкурс, а не как биржа: на один бриф приходит несколько клипов, модератор выбирает лучший. Для контент-завода это плюс — больше контента и выше качество на единицу брифа.
- **Воркеры, не прошедшие модерацию, работают впустую.** При M=5 четверо получат ноль. Это надо явно показывать в UX до взятия задания, иначе репутация площадки упадёт.
- Цена: +1 тип аккаунта, +1 инструкция (`claim`), +1 PDA-деривация. Заметно, но это единственная точка, где решение нельзя отложить.
- `max_claims` — параметр на задание, а не глобальная константа. Пилот сможет выставить `max_claims = 1` и получить эксклюзив без изменения схемы — то есть вариант «эксклюзив в пилоте, M в v2» доступен бесплатно.
