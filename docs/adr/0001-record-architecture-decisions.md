# ADR-0001: Формат записи архитектурных решений

- **Статус:** принято
- **Дата:** 2026-09-14

## Контекст

Мастер-промпт (раздел 0) требует: «Для каждого нетривиального решения создавай короткую ADR-запись в /docs/adr/». Нужен единый формат, чтобы решения можно было audит-ить и оспаривать постфактум.

## Решение

Каждый ADR — отдельный файл `NNNN-короткое-имя.md` с полями:

```
# ADR-NNNN: Заголовок
- Статус: proposed | принято | superseded by ADR-XXXX | отозвано
- Дата: YYYY-MM-DD
- Решает: QNN из docs/OPEN_QUESTIONS.md
```

Разделы: **Контекст** → **Решение** → **Последствия** (включая то, что решение ломает).

Правила:
1. ADR не перезаписывается. Изменение решения = новый ADR со статусом `superseded by`.
2. Если решение касается денег, юридического риска или mainnet — в поле «Статус» обязательно `proposed` до письменного подтверждения заказчика.
3. Номер ADR = номер вопроса в `docs/OPEN_QUESTIONS.md`, если ADR закрывает вопрос из реестра.

## Последствия

Каждый ADR — это точка, где агент отступил от текста промпта или заполнил пробел. Все они видны в одном месте и могут быть отменены заказчиком.
